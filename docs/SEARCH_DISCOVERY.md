# Search & AI discovery surface

How the public studio site stays fully indexable by traditional search engines
and AI discovery crawlers. Everything here is build-time and deterministic —
no runtime SEO hacks, no third-party SEO dependencies.

## Render-path truth

- `/` is the React front door. `scripts/build-discovery-spine.mjs` injects a
  static HTML document body (studio copy, project doorways, navigation) plus
  `Organization` + `ItemList` JSON-LD into `dist/index.html` after the Vite
  build, so non-JS crawlers read the full document immediately. React replaces
  the injected body on load; the claims in both come from `src/data.ts`.
- Every other public route (`/play`, `/press`, `/follow`, `/dispatches/*`,
  `/<project-id>`) is a fully static page generated by the same script from
  `src/data.ts`, with canonical URL, Open Graph/Twitter cards, one `<h1>`, and
  `Article` JSON-LD on dated dispatches.
- `src/data.ts` and `src/data/studioSignals.ts` remain the only owners of
  public project claims. The generator presents data; it never invents it.

## Discovery files (all generated or committed, served from the site root)

| File | Source | Purpose |
| --- | --- | --- |
| `robots.txt` | `public/robots.txt` | Allows `*`, Googlebot, Bingbot, OAI-SearchBot, ClaudeBot, PerplexityBot, Google-Extended; declares the sitemap |
| `sitemap.xml` | generated | Every public URL with per-entry `lastmod`, `changefreq`, `priority` |
| `llms.txt`, `llms-full.txt` | generated | Dense Markdown studio summary per llmstxt.org for AI crawlers |
| `manifest.webmanifest` | `public/manifest.webmanifest` | Web app identity (icons, theme colors) |
| `<indexnow-key>.txt` | `public/` | IndexNow ownership proof; key lives in `scripts/ping-indexnow.mjs` |
| `feed.xml` | generated | RSS dispatches feed (autodiscovery link in every page head) |

## Verification & indexing triggers

- `npm run seo:verify` — programmatic proof that the built `dist/` carries the
  static home copy, JSON-LD, meta tags, canonicals and single-h1 hierarchy on
  every route. Runs after `npm run build`; exits non-zero on failure.
- `VITE_GOOGLE_SITE_VERIFICATION` (or `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION`)
  environment variable: when set at build time, the verification meta tag is
  added to the home document head. Set it in the Vercel project settings.
- `npm run indexnow:ping` — submits every URL in the sitemap to the IndexNow
  endpoint (Bing, DuckDuckGo and AI search indexes that subscribe). Run after
  a deploy that changed public pages. `--local` reads `dist/sitemap.xml`;
  `--url /path ...` submits specific URLs.

## Headers (`vercel.json`)

Security headers on every route (`X-Content-Type-Options`, `Referrer-Policy`,
`X-Frame-Options`, `Permissions-Policy`), explicit `Content-Type` + short cache
for `robots.txt`/`llms*.txt`/`sitemap.xml`, RSS content type for `feed.xml`,
and long cache for versioned `/assets/*` and `/play/*` bundles. No
`X-Robots-Tag` header exists anywhere; nothing sets `noindex` except the
`404.html` fallback page (which returns HTTP 404 regardless).
